# v0.9.5 · 招式特效从嘴里发出

用户反馈：喷火龙的喷射火焰不是从嘴里喷出来的。原因是特效起点一直取的是“精灵框（345×320 网格格子）的中心”，和画出来的精灵本体没有关系。本版只改特效的起点 / 终点，不改引擎、不改数据结构的其它部分。

- **嘴部锚点**：新增 `tools/measure-mouth-anchors.py`，离线分析 Pokémon Showdown 动图的每一帧（透明度轮廓 + 厚度图 + 主体配色），找出“朝向对手、位置最高、跨帧稳定”的头部区块，取其朝向对手一侧的轮廓极点作为嘴部，结果以 GIF 画布比例写入 `src/data/sprite-map.json` 的 `frontMouth` / `backMouth`（2876 / 2881 张图成功，其余运行时退回“身体核心斜上方”的估计）。
- **人工校对表** `tools/mouth-overrides.json`：翅膀 / 手臂挡在头前的物种（喷火龙及两种 Mega、水箭龟、烈咬陆鲨、路卡利欧）用人工读数覆盖自动结果，脚本会自动合并。
- **运行时**：`src/ui/app.js` 新增 `spritePoint(side, kind)`，用 `PKMSpriteAnchor.project` 把锚点换算到屏幕坐标（已含 object-fit 留白、缩放、位移、镜像）。火 / 水 / 冰 / 龙 / 一般 / 毒 / 钢系远程特效和龙系光束从 **嘴部** 发出，其余属性从身体核心发出；终点统一为对方的 **身体核心**（不再是对方精灵框中心），命中闪光也移到身体核心上。
- 页脚与资源参数统一为 **v0.9.5**（`sprite-map.json?v=0.9.5` 强制刷新缓存）。

# 宝可梦对战（自研版）

一个为 SillyTavern 角色卡设计的宝可梦对战游戏：对战本体是独立的静态网页（可部署到 GitHub Pages），角色卡只负责剧情、队伍存档（MVU 变量）和触发战斗。架构思路参考了同类卡的分层方式，代码与素材均为本项目原创/公开数据生成，不复制任何现有项目的代码。

## 现在能玩什么（第一至四阶段 A）

- 单打对战，双方最多 6 只宝可梦，可换人
- 完整 18 属性克制表、种族值/个体值/性格计算、官方伤害公式（含 STAB、会心、0.85–1.00 随机数、灼伤减攻）
- 优先度与速度判定、命中/闪避与能力等级（攻防特攻特防速度 ±6、命中/闪避）
- 异常状态：麻痹（减速+概率无法行动）、灼伤、中毒、剧毒、睡眠、冰冻、混乱、退缩
- 招式追加效果：能力变化、状态赋予、吸取、反伤、回复、连续攻击（按 Showdown 数据格式解释）
- 天气与场地：晴/雨/沙暴/雪、电气/青草/薄雾/精神场地、戏法空间、重力、顺风
- 场地钉子与墙：隐形岩、撒菱、毒菱、黏黏网、反射壁、光墙、极光幕，高速旋转/清除浓雾/大扫除可清除
- 四档敌方 AI（easy 经常失误 → expert 会估算斩杀、换人应对克制）
- 数据：Showdown 公开 JSON 生成的 1518 条图鉴 + 954 条招式 + 1121 个物种的第九代学习面（见 `tools/build-data.mjs`）
- 队伍编辑器：为双方各编辑 6 只宝可梦的物种、等级、性格、特性和 4 个招式；招式列表按 Gen 9 学习面过滤，支持合法性校验、自动配招、随机队伍和浏览器本地保存
- 四大战斗机制（单打）：超级进化（形态种族值、属性与特性切换）、Ｚ招式（攻击型与变化型效果）、极巨化与超极巨化（体力翻倍三回合、极巨招式与追加效果、极巨防壁）、太晶化（防御属性改变与本系加成规则）；每方每种机制一场只能使用一次，在选择招式前点机制按钮发动
- 特性与道具：已实现一批高频特性（威吓、静电、引火/蓄电/储水/避雷针、漂浮、结实、多重鳞片、技术高手、强行、天气/场地入场特性等）与常用道具（剩饭、生命宝珠、讲究三件套、气势披带、凸凸头盔、厚底靴、弱点保险、树果等）；未实现效果的特性/道具会在校验时明确提示
- 界面设计：参考宝可梦角色卡的横版战斗界面——一整块横版战斗屏，敌方信息左上、敌方精灵右上、我方精灵左下、我方信息右下，底部左为战斗记录、右为招式与换人指令台；队伍状态改为小球点阵，界面文字、宝可梦名称、招式、特性、性格与日志均已汉化；全部 1518 条图鉴条目均已逐只校验正面与背面图：敌方用正面、我方用背面，优先动图；无独立形态动图时回退到同视角基础图，不再显示气球占位
- 对接预留：支持粘贴 `<PKM_BATTLE>` 配置开战、URL `?config=` 传参、宿主页面 `postMessage` 下发配置、结束后回发 `PKM_BATTLE_RESULT`

暂未实现（已在路线图中排期）：双打 2v2、其余低频/复杂特性与道具、专属 Z 招式/专属极巨招式完整效果、原始回归、PP 耗尽时的挣扎、捕获/成长、地图与 NPC 数据库、动画与音效。

## 本地运行

不要直接双击 `index.html`（浏览器会拦截读取数据 JSON）。在本目录开一个静态服务器：

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000
```

运行引擎测试（需要 Node 18+，无第三方依赖）：

```bash
node tests/run-tests.mjs
node tools/build-data.mjs   # 重新生成图鉴、招式与学习面数据
node tools/build-zh-names.mjs  # 重新生成简体中文名称数据
node tools/build-sprite-map.mjs  # 逐只校验并生成正背面精灵图映射
```

## 部署到 GitHub Pages（你自己的仓库）

1. 在 GitHub 新建一个仓库（比如 `pokemon-battle`），把本目录的全部文件放进仓库根目录并 push。
2. 仓库 Settings → Pages → Build and deployment 选择 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存。
3. 等一两分钟，访问 `https://你的用户名.github.io/pokemon-battle/` 就能打开对战页面。
4. 把这个地址填进角色卡的正则/桥接脚本里（见 `sillytavern/` 文件夹的对接说明），酒馆里就能调用。

## 战斗动画表现（0.8.2）

- 登场/退场动画（0.8.1，参考宝可梦角色卡的节奏重新实现）：无精灵球道具，全靠精灵本体——我方登场时从下方升起、带回弹过冲站稳，敌方从上方坠落缩小站稳；被击败或主动换人时，精灵闪烁着沉降消失并保持隐藏。开局双方、击倒后自动换上、玩家主动换人均已接入。
- 阴影对位修正（0.8.2）：重测全图鉴横向站立点——阴影改对准“脚”（高列底部聚类，排除尾巴/尾焰干扰），皮卡丘等尾巴较重的宝可梦不再出现脚与阴影错位。
- 完整整合包（0.8.3）：将 0.1–0.8.2 全部内容整合为一个可直接导入的完整包；数据文件加载加版本参数，避免浏览器缓存旧数据。
- 变身图标对齐修复（0.8.4）：超级进化等机制的图标此前被精灵图的 320px 尺寸规则误伤、撑成巨图跑偏，现已隔离尺寸规则，并改为按精灵本体实际渲染中心定位。
- 精灵脚底对齐（0.7.2）：离线逐张测量全部 2881 张精灵图的脚底位置与横向身体重心（`tools/measure-sprites.py`，数据写进 `sprite-map.json`），运行时把每只宝可梦的脚对齐到地面阴影、阴影横向跟随重心移动，不再出现脚悬空或踩不准阴影。脚底数据取全部动画帧的第 30 百分位（0.7.3）：动图自身浮动时按偏低位置对齐，避免只按第一帧对齐导致大半个循环周期都浮空。
- 战场比例（0.7.1）：按近大远小放大精灵——我方 320px、敌方 185px（极巨化另乘倍率），名字/血条/介绍与底部指令台整体瘦身，指令台高度 228→190px，战场更突出。
- 招式特效按属性区分（0.7.0）：火焰是橙红火焰喷流、雷电是锯齿状闪电、水/毒是泡泡弹道、冰是冰晶碎片、地面/岩石是头顶落石、飞行/恶是斩击、超能力是扩散波纹、龙是能量光束……18 个属性全部覆盖，不再是清一色光束。
- 物理招式为突进 + 对应属性的冲击爆点；特殊招式有专属弹道；变化招式显示对应属性的光环与上升微粒；敌方出招同样有特效；Z 招式播放放大版特效。
- 命中时目标会抖动并出现冲击爆点；受伤、回复、异常状态和倒下都有对应表现。
- 变身过场为“彩色剪影 → 图标浮现 → 白光换图揭示”：超级进化时精灵先变成流动的彩虹色剪影（不再是黑色）并轻微抖动，再显示自绘 Mega 图标，最后在白光最亮处切换为超级形态并以冷却发光收尾；极巨化/超极巨化使用红色爆发长大与红 X 图标，揭示后头顶保留三团红云；太晶化使用按太晶属性着色的结晶闪光与太晶宝石图标，揭示后头顶保留小太晶宝石；Z 招式改为完整的金色蓄力——精灵金色辉光颤动蓄满、身后升起光柱、脚下扩散光环并飘起金色火花，Z 图标放大浮现后释放粗光束。
- `src/ui/icons/` 内是本项目自绘的 SVG 图标；搜集回来的原作参考图只放在本地 `reference/animation/` 做设计对照，不作为游戏运行时素材。
- 动画只属于界面表现层，不改变引擎计算、伤害、回合或酒馆协议。

## 变身动画时序（0.6.5）

- 参考角色卡的播放顺序重构：玩家变身先在当前精灵上播放动画、再结算回合；敌方变身会在第一帧前切回旧形态。
- 精灵图始终只有一张：旧形态先变成流动的彩虹色剪影并轻微抖动，随后白光爆发并在最亮时切换为新形态，最后以冷却发光收尾；极巨化是同一张图红色爆发长大，太晶化是同一张图结晶闪光，Z 招式是金色光柱蓄力后出招。
